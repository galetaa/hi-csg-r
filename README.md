# HI-CSG-R

**HI-CSG-R: структурно-диагностическое графовое представление русского
рукописного текста для офлайн-HTR**

Репозиторий содержит завершённую научную работу, исходный код метода,
экспериментальные манифесты, результаты, отчёты, историю научных решений и
финальную рукопись. Проект исследует не только точность распознавания, но и
структурный контроль входных изображений, причины ошибок и надёжность
автоматически распознанного текста.

## Научная проблема

Офлайн-HTR работает со статическим изображением и не имеет доступа к реальному
движению пера. Ошибка распознавания может быть вызвана архитектурой модели,
недостатком обучающих данных, фоновыми линиями, потерей тонких штрихов,
разрывами скелета, соседним текстом или неудачной предобработкой. Обычная схема
«изображение → строка» не разделяет эти причины.

HI-CSG-R вводит промежуточное структурное представление видимых штрихов. Оно
используется для диагностики переднего плана, скелета, графа и риска ошибки,
но не объявляется реконструкцией реального процесса письма.

## Объект, предмет и цель

**Объект исследования** — изображения русскоязычного рукописного текста из
нескольких доменов.

**Предмет исследования** — методы подготовки, распознавания и структурной
диагностики рукописных изображений, влияющие на точность и надёжность
CRNN-CTC.

**Цель работы** — разработать и экспериментально оценить структурно-
диагностический конвейер офлайн-HTR, объединяющий:

1. воспроизводимую image-only модель CRNN-CTC;
2. подготовку многодоменных русскоязычных данных;
3. релевантное расширение обучающей выборки;
4. граф HI-CSG-R как описание видимой структуры штрихов;
5. анализ надёжности и выборочное принятие предсказаний.

## Данные

Основной русскоязычный вывод опирается на три источника:

| Набор данных | Роль в исследовании |
|---|---|
| Cyrillic Handwriting | кириллические слова и короткие фразы; один из основных доменов HTR |
| HKR Words | дополнительный домен русско-казахских слов и фрагментов |
| School Notebooks | сложный тетрадный домен с фоновыми линиями, соседним текстом и неоднородным качеством |

Дополнительные и диагностические источники:

- HWR200 — стрессовые условия получения изображений;
- HKR Forms — страничные и формовые данные для диагностики;
- IAM — англоязычный ориентир ранних baseline, не входящий в основной русский вывод.

Базовая смешанная обучающая выборка содержит 30 000 примеров: по 10 000 из
Cyrillic Handwriting, HKR Words и School Notebooks. В варианте `+10k` добавлены
9 998 пригодных контекстных фрагментов School Notebooks, выбранных только из
обучающей части.

Основной тест содержит 5 563 примера:

- Cyrillic Handwriting — 1 563;
- HKR Words — 2 000;
- School Notebooks — 2 000.

Поздние HKR+School эксперименты используют отдельный строгий page-disjoint
протокол без пересечения страниц между train, validation и test.

## Метод HI-CSG-R

HI-CSG-R расшифровывается как **Handwriting-Informed Canonical Stroke Graph
Representation** — каноническое графовое представление видимых штрихов
рукописи.

Общая последовательность структурной ветви:

```text
изображение
  → нормализация и выделение текстовой области
  → бинарная маска переднего плана
  → скелетизация
  → поиск endpoints и junction clusters
  → трассировка рёбер
  → компоненты, кандидаты петель и предупреждения
  → нормализованные структурные признаки
```

Граф формально описывается как `G = (V, E, X_V, X_E)`, где `V` и `E` — узлы
и рёбра, а `X_V` и `X_E` — их признаки. Сохраняются координаты, степени узлов,
компоненты, длины рёбер, упрощённые полилинии, proxy ширины видимого штриха и
диагностические flags.

Представление является детерминированным при одинаковом входе и параметрах.
Оно не восстанавливает порядок написания, скорость, фактический нажим или
реальную траекторию пера.

## Модель распознавания

В качестве контролируемого image-only baseline используется CRNN-CTC:

- свёрточные блоки с каналами `64 → 128 → 256 → 256`;
- GroupNorm и ReLU;
- уменьшение ширины изображения в 4 раза;
- сохранение четырёх вертикальных bins вместо полного усреднения высоты;
- линейная проекция в 256 признаков;
- двухслойный bidirectional LSTM с hidden size 256;
- CTC-классификатор и greedy decoding.

Основной протокол обучения:

- seed: 42, 43 и 44;
- optimizer: AdamW;
- learning rate: `0.0005`;
- weight decay: `0.0001`;
- batch size: 16;
- gradient clipping: 5.0;
- до 80 эпох;
- линейное изменение CTC blank penalty от `-2.0` к `-0.4`;
- финальное декодирование с параметрами, выбранными по validation, а не test.

## Основной численный результат

Релевантное расширение обучающей выборки улучшило CRNN-CTC во всех трёх
основных запусках.

| Seed | CER baseline | CER +10k | ΔCER |
|---:|---:|---:|---:|
| 42 | 0.145446 | 0.135127 | -0.010319 |
| 43 | 0.148931 | 0.137146 | -0.011785 |
| 44 | 0.162917 | 0.134165 | -0.028752 |
| Среднее | 0.152431 | 0.135479 | -0.016952 |

Среднее относительное изменение CER составляет `-10.89%`. Дополнительные
метрики также улучшились:

| Метрика | Baseline | +10k | Изменение |
|---|---:|---:|---:|
| CER | 0.152431 | 0.135479 | -0.016952 |
| WER | 0.528311 | 0.488990 | -0.039321 |
| Полное совпадение | 0.424232 | 0.465037 | +0.040805 |

### Доменный эффект

| Домен | Средний CER baseline | Средний CER +10k | Средний ΔCER | Улучшенных seed |
|---|---:|---:|---:|---:|
| Cyrillic Handwriting | 0.203650 | 0.189479 | -0.014170 | 3/3 |
| HKR Words | 0.101083 | 0.091986 | -0.009097 | 2/3 |
| School Notebooks | 0.163752 | 0.136771 | -0.026981 | 3/3 |

Наиболее сильный и устойчивый эффект наблюдается на School Notebooks.

## Контроль механизма улучшения

Same-size и page-disjoint контроли подтвердили пользу дополнительных
релевантных данных, но ограничили более сильную интерпретацию:

- строковый вариант устойчиво лучше базовой модели;
- случайные crop-примеры сопоставимого объёма дают близкий результат;
- доменно близкие School-word примеры в строгом page-disjoint сравнении не
  хуже строкового варианта;
- поэтому весь эффект нельзя приписывать только естественному строковому
  контексту.

Защищаемый вывод: **состав, качество и доменная релевантность дополнительной
обучающей выборки являются существенным фактором качества HTR**.

## Структурная диагностика

Ручная диагностическая проверка выполнена на 200 примерах.

| Показатель | Значение |
|---|---:|
| пригодность foreground | 1.000 |
| пригодность скелета | 1.000 |
| пригодность графа | 1.000 |
| общая диагностическая пригодность | 1.000 |
| остаточные линии | 44 случая |
| потерянные фрагменты чернил | 17 случаев |
| соседний шум | 3 случая |
| ложные чернила | 1 случай |

Результат подтверждает пригодность графа для диагностики на проверенной
подвыборке, но не доказывает полную топологическую правильность каждого графа.

## Выборочное принятие предсказаний

| Модель риска | ROC-AUC | CER@90 | CER@80 | CER@70 | CER@50 |
|---|---:|---:|---:|---:|---:|
| только структурные признаки | 0.603645 | 0.132357 | 0.133754 | 0.134980 | 0.139034 |
| confidence CRNN-CTC | 0.796691 | 0.107670 | 0.091126 | 0.077067 | 0.056861 |
| confidence + структура | 0.812214 | 0.107610 | 0.092165 | 0.080918 | 0.063897 |

Основной сигнал даёт уверенность CRNN-CTC. Структурные признаки повышают
ROC-AUC, но не улучшают confidence-only вариант на каждом уровне покрытия.

## Graph fusion

| Вариант | CER | WER | Полное совпадение |
|---|---:|---:|---:|
| image-only +10k | 0.135127 | 0.492426 | 0.463599 |
| graph fusion +10k | 0.133805 | 0.478634 | 0.456229 |
| zero-graph ablation | 0.153587 | 0.536638 | 0.415244 |

Zero-graph ablation показывает, что модель использует графовую ветвь. Однако
преимущество graph fusion не подтверждено на нескольких seed, а доля полностью
правильных ответов ниже image-only варианта. Поэтому результат считается
поисковым.

## Ограничения

- Структурная проверка не является полной топологической gold-разметкой.
- Не выполнена независимая разметка вторым аннотатором.
- Нет полноценного конкурентного внешнего русскоязычного HTR baseline под тем
  же протоколом.
- Writer metadata доступна не для всех наборов, поэтому общий writer-disjoint
  вывод невозможен.
- Строгий page-disjoint контроль выполнен только для HKR+School части.
- Механизм улучшения нельзя свести исключительно к строковому контексту.
- Graph fusion остаётся exploratory результатом.

переноса нет. Архив сохраняет полную реализацию, но не является текущим API.

## Проверка завершённого исследования

Установка окружения и полный быстрый контроль:

```bash
uv sync
uv run python -m src.pipeline status
uv run python -m src.pipeline verify
uv run python -m src.pipeline reproduce-lite
uv run pytest
```

`reproduce-lite` без GPU и датасетов проверяет ключевые числа v11 и SHA-256
84 сохранённых артефактов. Для отдельного аудита данных и проверки готовности
полного переобучения:

```bash
uv run python -m src.pipeline audit-data
uv run python -m src.pipeline reproduce-full
uv run python -m src.pipeline regenerate-tables
```

На текущем устройстве `reproduce-full` ожидаемо сообщает `BLOCKED`: отсутствуют
изображения и model weights. Это не влияет на evidence-level проверку, потому
что versioned predictions, summaries, configs, histories и manifests доступны.

Проверка JSONL-манифеста:

```bash
uv run python -m src.pipeline validate-manifest path/to/manifest.jsonl
```

Сохранение provenance snapshot текущего состояния:

```bash
uv run python -m src.pipeline snapshot --out provenance.json
```

Raw и processed изображения не хранятся в Git. IAM и HKR восстанавливаются
только вручную по условиям владельцев; HWR200 и School Notebooks доступны через
Hugging Face с закреплёнными revisions, Cyrillic Handwriting — через Kaggle v4.
Полная карта источников приведена в [`research/datasets.yaml`](research/datasets.yaml),
а процедура — в [`docs/DATASETS.md`](docs/DATASETS.md).

План автоматического получения данных без фактического скачивания:

```bash
uv sync --group data-download
uv run python -m scripts.download_datasets plan
```

Публичные HWR200, School Notebooks и Cyrillic Handwriting поддерживают
`download --execute`; для IAM/HKR сценарий выводит ручной маршрут и проверяет
ожидаемые архивы. Скачивание, безопасная распаковка и локальные SHA-256 подробно
описаны в [`docs/DATASETS.md`](docs/DATASETS.md).
